# 用 web-access 爬素材：一步一步教程（名称、数据、图片）

> **给 agent 看的。** 用户给了旧主页 / 社交媒体链接，或要补真实信息（获奖名称、项目指标、
> 机构名、时间线……）时，用 WorkBuddy 的 **web-access** skill 联网去抓，**不要凭印象编**。
> web-access 统管所有联网操作：搜索、网页抓取、登录后操作。
> 简单的静态单页也可以走 `scripts/fetch_refs.py --url <地址> --download`（更快，够用）。

## 什么时候用它

| 场景 | 抓什么 |
|---|---|
| 用户丢来链接（旧主页 / GitHub / 豆瓣 / 小红书 / 微博 / B站 / Behance / 学校页面…） | 作品名、一句话简介、栏目名、时间、图片 |
| 专名要核准（奖项全称 / 比赛名 / 机构名 / 产品名 / 年份） | 搜官方页面确认拼写和年份，别写错别字、别编 |
| 图片素材不够 | 从用户自己的公开主页抓原图（比生成图**便宜且真实**，能复用就不生图） |
| 作品要放真实数据（播放量 / 获奖记录 / 发表信息） | 原始数字和出处，写进 `data.json` 前先跟用户核对 |

## 一步步怎么做

1. **先跟用户对清单**：要抓哪几个链接、哪些页面是公开的。
   登录才见的内容（微博 / 小红书常见）**要用户配合在浏览器里登录**，别要密码、别绕登录墙。
2. **逐个链接抓**（调 web-access skill；静态单页可改跑 fetch_refs.py）：
   - 名称类：作品名、栏目名、机构名、奖项全称 —— **原样保留**，这是要写进站里的专名；
   - 数据类：年份、指标、条目数 —— 记下数字和出处页面；
   - 图片类：拿到直链后下载到 `portfolio/assets/` 对应目录
     （作品卡 → `cover/`，奖项图 → `award/`，项目截图 → `projects/`，摄影 → `photo2/`）；
   - 布局参考：主视觉 / 主色 / 栏目结构存进 `refs.json`。
3. **回来分三堆**：
   - **文字 → 重写**。抓来的原文只当参考，一句都不能原样进站（版权 + 语气）；
   - **名称 / 数据 → 核对后填** `data.json`（拿不准的搜官网二次确认，或发给用户确认）；
   - **图片 → 换掉占位图**，同名覆盖即可。
4. **生成前体检**：`build.py --site <目录> --check`，引用一个不缺再交。

## 硬规矩

- **文字必须重写**：标题、简介、说明都重写；只有**专名和数字**原样保留。
- **图片注明来源**：哪张从哪抓的记下来（`refs.json` 或口头），交付时跟用户说清
  「这几张来自你的旧主页」。
- **只抓用得上的**：图 / 名 / 数据 / 时间线。不做全站镜像，不爬无关页面。
- **登录墙不硬闯**：需要登录就让用户操作，抓不到就明说「这几条没抓到」，别编。
- **抓来的事实要过体检**：日期、奖项名这类写进 `data.json` 的信息，错一个字用户会被人问穿。

## 跟用户怎么说（可直接发）

> 你把链接发我就行 —— 旧主页、社交账号、GitHub 都可以。我去把上面的作品名、数据、
> 图片抓下来：**文字我会重新写，不会照抄**；名字和获奖这类信息会原样保留、跟你核对。
> 有些页面要登录才看得到（比如微博），到时候可能需要你在浏览器里点一下登录。

## 和其它环节的接口

- 抓下来的名字 / 数据 → `data.json` 对应字段（结构见 `data-schema.md`）；
- 图片 → 按「素材读取规则」归类，视频页的视频**仍然只配封面**（见 SKILL.md「素材读取规则」）；
- 风格参考（主色 / 版式） → 只作风格来源，**换文案**（SKILL.md ① 的硬规矩）。
