# 工作流程与硬规则

## 三道闸：不截图汇报 / 不自动上线 / 每次上线单独授权

用户明确立过的规矩，**任何时候不许绕过**：

1. **「生成网页 ≠ 发布。」** 生成 `index.html` 只是产出本地文件，**不等于上线**。
2. **「每次上线必须经用户同意，一次一议。」** 上线是一次独立动作，每次单独授权。
3. **「以后你直接把改好的网页给我，不用去截图。」**
   **「以后不用先上线到网站里面，而是先发来给我看一下。」**
   → 验收方式 = 给**本地文件路径**（用 `present_files` 打开预览），**不是截图、不是自动 deploy**。

> 顺序永远是：**改完 → 给本地文件 → 用户点头 → 才上线。**

## 改内容前：先核基线

用户会**自己**用后台改 `data.json`，而且改得比 AI 勤。动手前必须：

1. 看时间戳链：`ls -la --time-style=+%m-%d\ %H:%M:%S portfolio/data.json portfolio/_bak/`
   （后台每次保存自动产一份 `data-bak`，这就是用户的改动轨迹）。
2. 如果 `data.json` 的时间戳比上次交付的还新 → **以用户当前版为基线**。
3. **先备份再写**（`_bak/data_before_<用途>_<时间戳>.json`）。
4. 用**文件名/标题**定位目标，**别用下标**（用户删过整组，下标会漂）。
5. 写完做**全量 diff**，确认只动了目标字段。

## ⚠️ 用户的删改 = 决定，不是疏漏

用户说「我改的基础上接着改 / 不要往回滚」时：
**他删掉的句子、段落、结尾一律不许补回来**，哪怕你认为那内容有价值。
只允许在他保留的文本上做：修语法硬伤、补漏字标点、轻微顺滑。
觉得某处删了有风险 → **只在回复里提一句让他决定，不落进文件**。

## 流程只有一处定义

流程（六个阶段、入口分流、每步的完成判据和失败回退）**只在 `SKILL.md`「标准流程」写一遍**，
配图是 `references/flow.svg`。这份文件不再复述流程 —— 之前这里有一份「五步」清单，
和 SKILL.md 的编号对不上，也和 `setup_site.py` 打印的 `[1/5]`—`[5/5]` 对不上，
三套编号同时存在，看的人必然按错的那套走。

下面只放流程之外的东西：交付形式的体积参考、图片规范、加页/下线、批量场景。

## 交付形式：让用户选，别替他定

| 用户想要 | 给什么 | 体积参考（Demo 站） |
|---|---|---|
| 只想看 / 发给别人看 | **单个 HTML**（`--pack html`） | 1.7 MB（图片全内联） |
| 要部署 / 要自己再改 | **压缩包**（`--pack zip`） | 0.6 MB |
| 说不清 | 两个都出（`--pack both`，非交互时的默认） | — |

- 单文件走 `pack_single.py`：`src` / `data-full` / `data-img` 等**所有**指向本地媒体的属性
  都会换成 `data:` URI，图标 `<link>` 会被摘掉（没必要为一个图标多背 5 份 base64）。
- 图片多的站（几百张原图）单文件会很难传，优先给 zip。
- 单文件**以后改内容要重新打包**，这点要跟用户讲清。

### 后台也能直接交付（v1.4.0）

不必非得绕回命令行。用户在后台点「生成网页」→ 弹窗 → 「存为单文件…」或「下载压缩包」，
产物直接落到浏览器给的保存位置：

- Chrome / Edge 走 `showSaveFilePicker()`，**弹系统「另存为」**，用户自己选目录；
- 其它浏览器退回 `<a download>`，落默认下载目录。

两条路的共同点：**用户全程不用知道文件在磁盘的哪个位置**。这就是 v1.4.0 的主要动机——
在此之前，后台只往页面底部打一行日志，产物在哪得靠嘴说。

## 上线：方案与「谁做什么」

六个选项（第一行不是上线，是「发文件」）：

| 方案 | 适合 | 动作 |
|---|---|---|
| **单文件 / zip** | 当面看、微信传 | 直接发文件 |
| **WorkBuddy 网页端** | 人在 WorkBuddy 里，最省事 | 说「发布上线」→「发布为应用」，平台托管给在线链接 |
| **GitHub 网页版** | 不装 git，全程浏览器 | github.com/new 建仓库 → 拖 `gh-pages/` 上传 → Settings → Pages |
| **GitHub Pages（git）** | 免费、可回滚 | 按上面的 ①~⑦，②⑥⑧ 要用户自己做 |
| **Netlify Drop** | 最快上线，不用 Git | 把 zip 或 `_publish_tmp` 拖进 app.netlify.com/drop |
| **自有服务器** | 已有域名空间 | `_publish_tmp` 全量覆盖，纯静态 |

要点：
- **`.nojekyll` 必须加**（`--github` 会自动写）。GitHub Pages 默认跑 Jekyll，
  会把下划线开头的目录吞掉。
- 站内全是相对路径，**放在任何子目录下都能跑**（`/repo-name/` 也没问题）。
- 不要直接发布 `portfolio/`：`_bak/`、`_shot/` 会跟着上去。
- 想绑自己的域名 → `custom-domain.md`（Cloudflare + GitHub Pages 一步一步指引）。

## 图片规范

| 目录 | 用途 | 命名 |
|---|---|---|
| `assets/hero/` | 首屏封面 `cover.jpg` + 头像 `avatar.jpg` | **固定名，换图直接覆盖** |
| `assets/about/` | 形象照 `portrait.jpg` | 固定名 |
| `assets/cover/` | 作品卡封面 | `cover-<日期>-<序号>.jpg`（后台上传自动命名） |
| `assets/award/` | 奖状图 | `award-<日期>-<序号>.jpg` |
| `assets/photo2/` | 摄影原图 `<key>_01.jpg`，缩略图在 `t/` | `<分类key>_<两位序号>.jpg` |
| `assets/projects/` | 项目截图 | `projects-<日期>-<序号>.jpg` |
| `assets/design/` | 设计物料（海报、门票、展签） | `design-<日期>-<序号>.jpg` |
| `assets/digital/` | 自媒体账号图（头像 / 视频封面） | `digital-<日期>-<序号>.jpg`，头像固定 `avatar.jpg` |
| `assets/papers/` | 论文内页 | `papers-<日期>-<序号>_p<页号>.jpg` |

- **导入的照片不沿用原文件名**（v1.22.0）：后台上传一律落成
  `<目录短名>-<YYYYMMDD>-<两位序号>.<扩展名>`（如 `cover-20261104-01.jpg`），
  论文/文档导入落成 `<目录名>-<日期>-<序号>_p<页号>.jpg`。序号按天递增、永不覆盖，
  重传同一张图得到新文件、旧图仍有效。好处：全 ASCII（zip 分发不乱码）、无括号
  （URL 不用转义、单文件内联不会漏）、按天分组好找。
  手工往目录里放图也建议照这个规则，`data.json` 里写相对路径即可。
- 摄影图片**必须**按 `<key>_NN.jpg` 命名，`key` 与 `data.json` 的 `photo.cats[i][0]` 对应
  —— 这一条**不改**：生成器按名字分组，改了就丢分类。
- `hero/cover.jpg`、`hero/avatar.jpg`、`about/portrait.jpg` 是**固定文件名** —— 
  生成器写死的引用，换图要同名覆盖（后台有 `overwrite` 参数专门处理这个）。
- 大图上传会自动压缩；后台列表走 `t/` 缩略图。

## 新增页面 / 整块下线

现在有两条路，**优先用后台**：

1. **后台「页面设置」**（推荐，v1.8.0）
   - 一张卡 = 一个页面 = 网页上一屏 + 导航里一项。卡上 ↑↓ 调顺序、「显示」开关隐藏、
     ✕ 删除（二次确认，**默认只从网页撤下，内容一条不删**）、「编辑」加板块。
   - 新建页面走「+ 新建页面」：**先选页面模板**（10 种，带版式缩略图 + 「备好几条内容」的说明）
     再起名。落盘是 `site.pages: [{id, show, nav, title, titleEn, intro, blocks:[{type}]}]`。
   - 一种内容只能挂在一页上；已在别页时会**整块挪过来**，原页空了自动收起。
   - 上限 10 页（`PAGE_MAX`）。每个页面对应左侧导航一项，编辑器跟着页面走。
   - 序号（一二三）只数**渲染出来的**页面，隐藏/空页不会占号。
   - 「联系」不进导航，走顶栏右上 CTA；关掉它 CTA 也一起消失（不会点出空锚点）。

2. **手改 data.json**
   - 整页下线：把那一页的 `show` 改 `false`（内容留着），或从 `blocks` 里删掉那块。
   - 某类内容不要了：删顶层键（如 `digital`）→ 该板块自动跳过，所在页若空了整页不渲染。
   - `site.pages` 整块删掉 → 回退到 `site.sections`（老格式）或内置默认顺序。
   > ⚠️ 老格式 `sections` 判空用的是 `is None` 而不是真假：空数组是**有效配置**。
   > 新格式 `pages` 没有这个问题，写 `[]` 就是「什么都不要」。

3. **加全新的板块类型**（`work/photo/papers/...` 之外的新 key）才需要改代码，三处都要动：
   - `build/gen_site.py`：`BLOCK_TYPES` 里注册、`NAV_LABEL` 给短名、写组装段
     （用 `begin_sec/end_sec` 包起来、标题里用 `@@N@@` 占位交给末尾统一填序号、正文用 `E()` 转义）；
     可选类型还要加进 `_OPTIONAL`（没数据时整块跳过）。
   - `admin/index.html`：`BLOCK_EDITOR`（有编辑器才允许建页）、`blockCount`（删除弹窗要报数）、
     `PAGE_TPL`（模板卡）、以及一份编辑器 DOM（`data-blk="新key"`）。
   - `assets/data_skeleton.json`：给一个空壳（`items: []`），否则新站里这张模板卡会是灰的。

## 批量场景的注意点

同一套模板给多人用时，**每人是独立目录 + 独立 `data.json`**：

- 一人一个站点根目录，互不共享文件（`build/gen_site.py` 与 `admin/index.html` 都是拷贝过去的副本，
  这样将来单独改某个人的版式不会影响别人）。
- 模板升级后要同步到已有站点，得**逐个覆盖这两个文件**（覆盖前先备份，`_bak/` 里留一份）。
  只覆盖生成器会出现「后台能建页、网页却没这页」的错位。
- 后台端口会冲突：多站同时开时用 `SITE_PORT=8849 python admin/server.py` 指定端口。
